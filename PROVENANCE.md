# Provenance

This repository was created on 2026-10-21 from the research repository `efficient-vlm` (local path `/home/huynhvien/projects/efficient-vlm`, commit `50eaa23`; the layout before its own reorganization is tagged `pre-reorg-2026-10-20`). Nothing in the research repository was changed.

What was copied, and how:
- **Method** (`leaf/`, `baselines/`): copied from the research repository's `leaf/` package (itself the reorganized `models/`, `planner/`, `evaluation/`).
- **Experiments** (`leaf/reproduction/`): the campaign scripts and their helpers, ported with new module names, new import paths, paths relative to this repository, the key renames below and English text. Computations are unchanged: every analysis output was recomputed from the raw results and compared with the original (identical after the renames), and every table and figure of the paper is regenerated identically (`leaf report tables | figures`).
- **Raw results** (`results/`, not in git): copied by `tools/migrate_results.py copy`; then stored paths of the old machine were made repo-relative (`relocate`), keys were renamed (`rename-keys`), and seals / recorded file hashes of the rewritten JSON were recomputed (`reseal`). `results/MANIFEST.json` lists, for every file, its source path, the sha256 of the source and the current sha256. Per-image arrays (`.npz`) and timings are byte-identical to the source.
- **Schedules** (`schedules/`): `schedules/leaf/` is the release of the paper's method; the other folders are the schedule exports of the campaigns, renamed.
- **Paper** (`paper/`): the final sources (`main.tex`, `supp.tex`, bibliography, figures, tables); labels renamed (below).
- **LEAF-M0 campaign code** stays in the research repository (separate working copy `~/.codex-vien/worktrees/5d6e`). This repository keeps its results (`results/leaf_m0*`), its schedules (`schedules/leaf_m0/`) and a port of its forecast-quality experiment (`leaf/reproduction/experiments/forecast_quality.py`, which reproduces the stored results exactly).

Not copied: code the paper does not use (archived in the research repository: earlier PID / I-term prototypes, CLIP and segmentation extensions, search-method comparison, mean-attention ablation), internal reports and plans, superseded orchestration scripts.

## Deviations from the original runs

- `leaf.evaluation.runner.build`: the experimental kind `ipd` (I-term roles) raises an error; its code is archived in the research repository.
- `tests/test_determinism.py` no longer includes the two `ipd` arms; `tests/test_planner.py` no longer runs the archived A6 search method.
- `tests/test_latency_pricing.py`: the check that the campaign's source files are unchanged at their old paths is skipped (they were ported).
- Two inputs of the paper had no generator; they now have one, verified against the stored files: `results/main_comparison/ablation_report.json` (`leaf experiments run campaign_reports ablation`) and the forecast-quality table (`leaf/reproduction/report/build.py`). The search-cost throughputs (`results/search_cost/throughput.json`) can be re-measured (`leaf experiments run search_cost measure`; timing noise applies).
- Hand edits of the final paper tables (captions, kappa -> alpha, removed rows, probe count) are now part of the generators.

Also copied into `results/` (outside the manifest, which covers the campaign folders above):
- `results/forecast_rank/audit.json` <- `artifacts/paper/v2/data/forecast_rank_audit.json` (per-group energy of the rank-32 forecast; also re-computable with `leaf experiments run forecast_rank`);
- `results/leaf_m0_summaries/` <- `artifacts/paper/v1/tools/paper_final_data.json`, `second_campaign_data.json` (collections of the LEAF-M0 campaigns) and `artifacts/reports/paper-final/*.md` (its per-backbone pair tables), read by the LEAF-M0 table and figure.
